# Design decisions — R1.1

| Decision | Reason / boundary |
|---|---|
| Keep the real 1.28-inch screen | A documented Adafruit board and GC9A01A driver support a first build. Concept-art screen proportions are aspirational. If standing readability fails, make a deliberate new hardware revision. |
| Transfer the rival vibe through details | Charcoal octagonal bezel, thin muted-gold rim, crimson cheek/base band/buttons, shallow panel marks and original pixel bat preserve personality without a complex shell. |
| Flat 40 × 1 mm window | An accessible, replaceable cover. A fishbowl lens remains a later optical experiment requiring glare/distortion tests and its own retention design. |
| Listen on a buffered dry branch | Keeps prototype software out of the audible signal path. The passive attenuator is not a high-impedance guitar preamp. No audio output or mute function is implemented. |
| USB 5 V only | Avoids adding a 9 V protection/regulation design to the first build. USB ground noise must still be tested with the actual rig. |
| Participation XP, one quest fragment per session | Clear and testable motivation. Audio activity is not evidence of good timing, intonation or technique. No calendar clock means no true daily streaks. |
| Five STEP service groups | Makes review and removal of the lid/carrier practical. Hardware belongs to its mating assembly; wiring reserves are separate. |
| Python construction plus neutral solids | Reproducible source and broad CAD interoperability. STEP has no native feature history. |
| Shared C++ logic and renderer | Host simulation exercises the actual rules/pixels. It injects signal measurements rather than pretending to emulate SGTL5000/DSP. |
| Shared device state machine (`app.h`) | Calibration, hold actions, notices, auto-save and the ordered two-slot write live in one header driven by both the sketch and the simulator through tiny adapters (clock, controls, observations, byte store). Scenario scripts and golden frames then test the firmware's real behaviour, including power cuts mid-write. |
| Shared YIN analyzer in the foreground (`analyzer.h`) | The audio interrupt only copies blocks and accumulates level; pitch runs in `loop()` on a 2048-sample window. The same code processes the reference WAV and Mac input on the desktop. `VEX_PITCH_PJRC` keeps the PJRC detector selectable for bench comparison. Desktop results are not SGTL5000/gain/latency evidence; `yin_us` telemetry exists so the bench can measure cost. |
| Presentation facts stay out of the save record | Fragment/level-up banners, strum animation and the session summary derive from runtime fields in `App`; the version 1 record is unchanged, so no migration was needed. |
| Two CRC-protected save records | Recovers the last valid slot after a damaged write. Hardware power interruption and EEPROM wear still need validation; changing format requires migration. |
| Lean AGENTS.md plus two task skills | Always-load context stays small; detailed procedures and evidence are read when relevant. No session-history importer is required. |
| Actual-CAD marketing images | Reuse checked-in STEP geometry and shared UI pixels with studio lighting/proposed finishes. Record hashes; no generative product imagery or invented hardware. |
| One repository, three readers | A hobbyist alone, a hobbyist with a mentor and a design studio read the same guide, CSVs and CAD. "Mentor" is defined once as any experienced second person; `docs/SOLO_BUILD.md` says what a solo builder covers alone or sends to a service; `docs/STUDIO_BRIEF.md` separates the fixed product contract (character, palette, screen, controls, input/power architecture, behaviour rules) from what a studio redesigns (enclosure manufacture, PCB, compliance, cost). Personal rig names were removed from data and guide text so the acceptance rows read for any rig. Agent-facing files stay, but the README routes humans past them. |
| Build-free review packing and bounded publication | Package reviewed outputs with a deterministic manifest. Send only changed small files; never repeat chunk/bridge loops or target builds for presentation work. |
| Browser workbench runs the firmware as WebAssembly | The earlier page proxied each action over HTTP to a native process and polled PNGs, so presses were dropped and timing was the poll's, not the device's. The shared headers now compile to WASM through a thin adapter (`simulator/web/vex_web.cpp`); the page owns a millisecond clock, real-time or faster, and blits the shared renderer's RGB565 frame directly. The native `build/vex-sim` remains the test oracle and `tools/web.py check` proves both render identical frames. No server logic to keep in sync. |
| Tuner states are labelled, and the last note fades | Waiting, listening, uncertain (`PITCH_UNCERTAIN` ≤ probability < `PITCH_VALID`), sounding, stale (1.5 s fade) and clipping each carry text, so colour never carries meaning alone and a decaying string does not blank the display. A strobe view was rejected: the pedal redraws every 200 ms over SPI. |
| Art is data in `art/`, imported into generated headers | PNG strips, a JSON manifest and a theme are what an artist can edit; `tools/make_sprites.py` validates them (palette, alpha, size, timing) and writes `theme.h`, `sprites.h`, `anim.h` and two font headers. Sprites stay 8-bit indexed at 1 KB per frame and the renderer allocates nothing. `tests/art_test.py` keeps committed headers honest. |
| Animation is locked to the display cadence | `DISPLAY_MS` (100) lives in `config.h`; `drawScreen` quantises time to it and every `frame_ms` must be a multiple, so host, browser and device show the same frame and a loop never repeats or skips a step (the 250 ms vs 200 ms strum jitter). |
| Dirty-band SPI flush with a RAM2 shadow | The renderer still draws a full frame, but the `.ino` compares rows against a `DMAMEM` shadow and writes only changed bands (`flush.h`, host-tested). Measured on the host: blink 2.4 KB, strum 31 KB, breath 60 KB per step versus 115 KB. Bench `tx_bytes` must confirm the 100 ms cadence before it is called verified; 200 ms remains a one-line fallback. |
| Bitmap display font from the bundled DejaVu Bold | Titles, note names and banners use an 8 × 12 proportional bitmap (`displayfont.h`) generated from `art/fonts/display.png`; captions keep the 5 × 7 tiny font. No runtime font engine, no new licence. |
| Measure the blocking flush before writing a DMA driver | The pinned Adafruit GC9A01A path writes pixels blocking on SPI. Rather than replace it on a guess, the sketch times each flush (`flush_us`, `flush_max_us`, `loop_max_us`), reports `tx_bytes`, and hides the panel writes behind a `Panel` adapter so an `ILI9341_T4`-style DMA driver can be dropped in later. The gate is a bench number: if `flush_max_us` stays under about a third of the cadence with dirty bands and no seams show, R1 keeps the library; otherwise the DMA work is opened with the measurement attached. |
| Device mirror over USB serial, not a second simulator | To debug with a Teensy attached, the sketch can stream the rows it just sent (band packets, CRC-32) and a compact state packet between its JSON telemetry lines (`link.h`); `tools/web.py serve --device` decodes them and the workbench's Device tab shows the real panel beside the WebAssembly frame with a live pixel diff, sends the bench switches and taps, and sparklines the telemetry. One protocol, one Python decoder (`tools/link.py`) shared by `make monitor`, the bridge and the tests. Off by default so plain serial stays readable; `make test` never touches a port and only `make upload` programs a board. |
| Bench switches live in the sketch, controls stay in `App` | `f b 1 2 l ?` toggle flush/diff/cadence/link from serial so panel questions are answered by flipping a switch, not by recompiling. `m q k` / `M Q K` synthesise 100 ms taps and 1.3 s holds that go through `App::controls` like the GPIO lines, so debounce and hold timing are the device's own and no second control path exists. |
| Animation `sequence` in the manifest | An animation may list its play order over the drawn frames (`[0,1,2,1]`), compiled into a flat step table (`VEX_ANIM_STEPS`) that `chooseAnim` indexes; the step index is what simulator, scenarios and telemetry report. A ping-pong breath or a repeated beat costs no extra 1 KB frame and no run-time work. The importer prints the screen rows each step will send, and `core_tests.cpp` holds idle to 30 % of the panel per step so long-running loops stay cheap. |
| Bench knobs are runtime, boot values are pinned | The SPI clock, codec line-in level and a display test pattern can be stepped from serial (`- + g G t`) so a wiring or sensitivity question is answered in seconds on the bench; nothing typed is persisted and a reset returns to `TFT_HZ` / `INPUT_LEVEL` in `config.h`, which change only with a measurement written next to the new value. The test pattern lives in the shared renderer and has a golden, so the host and the panel show the same thing. |
| Bench logs are evidence; the CSV fields stay human | Every session with a board is appended to `build/bench/<start>.jsonl` by the bridge and `make monitor`, and `make bench-report` reduces it to the numbers the acceptance rows and the DMA gate ask for (flush timing against the cadence, clipping seconds, reboots, uptime, fragments). The report prints; `acceptance_log.csv` and `measurements.csv` are filled by a person after looking at the panel and the meter, so an inferred value never masquerades as a measured one. |
| The print gate is derived from measurements | `MEASUREMENTS` in `project_data.py` maps each `measurements.csv` row to the `build_cad.py` constant it stands for, a tolerance and the parts that wait on it; `make measure-check` prints the deviation per row and lists every STL/DXF as print-now, ready or wait with the reason. The coupon and the two cosmetic inserts wait on nothing and print the day parts arrive; everything else waits for calipers. `check_project` keeps the data, the CSV and the files in agreement. |
| Crisper motion within the same budget | Six-step strum with notes that drift and fade, a breath confined to wings and collar plus an ear twitch, a squash-hop-land cheer, a rotating level-up sparkle, an ear-tilt listen and a rising Z sleep. Celebrations may move the whole bat (3 s); loops that run for minutes keep feet, head and floor planted. The ring's lead square eases gold → fade → ink → fade in 250 ms steps using theme colours only. |

Rejected for R1.1: large fictional screen, external ears/armor, custom dome, RGB spectacle, audio bypass, mains/battery/9 V conversion, broad game systems and speculative automatic technique scores. These are scope decisions, not permanent bans.

## Extension direction

- Retain the offline practice companion as the core product; richer coaching is optional.
- Preserve platform-independent practice rules and presentation data. Extract hardware adapters incrementally as features need them.
- Introduce versioned session summaries and a bounded USB application protocol before host-agent integration; existing debug serial is not that protocol.
- A coaching policy proposes supported exercises; the device owns measurement, session state and reward accounting. A general language-model planner belongs on an optional host initially.
- Port data/content contracts to V2 rather than promising processor pin or enclosure compatibility. No processor upgrade substitutes for measured recognition accuracy, readability or noise/strength testing.

The concrete boundaries, current gaps and acceptance sequence are in [EXTENSIBILITY.md](EXTENSIBILITY.md). These are architecture decisions for future implementation, not claims that those capabilities are present.
